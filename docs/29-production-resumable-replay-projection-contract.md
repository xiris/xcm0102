# Production Resumable Replay Projection Contract

## Purpose

P15B introduces deterministic projected remaining replay after interactive manager commands.

This is not yet full authoritative match resimulation. It is a pure projection layer that shows how manager decisions change future replay pressure while preserving the already-visible timeline.

## Module

```text
src/simulation/resumableReplayProjection.ts
```

Primary API:

```ts
projectRemainingReplay({ sourceEvents, currentMinute, commands })
```

Input:

- `sourceEvents`: original deterministic match events
- `currentMinute`: current interactive pause minute
- `commands`: recorded manager command history

Output:

- `events`: projected event timeline
- `score`: projected final score from projected events
- `diagnostics`: command-sensitive projection notes
- `signature`: deterministic projection signature

## Determinism rule

The same source event timeline, current minute, and command IDs must produce the same projected event list and signature.

No-command signature format:

```text
no-commands|54|7
```

Command signature format:

```text
cmd-054-01-change-mentality|cmd-054-02-change-pressing|54|9
```

## Already-visible event preservation

Events already visible at or before the current pause are preserved.

Projection rules only target future events after both:

- the command minute
- the current interactive replay minute

This prevents earlier commands from rewriting history after the user has already advanced past later events.
Visible events at or before the current replay minute are carried through in their original source order, even when future events are projected.
Late-match proactive commands that have no strictly future minute available do not inject tactical-shift events.
Non-proactive commands do not consume tactical-shift insertion slots, so a proactive command at 88’ can still use 89’ even if earlier commands in the same list only suppress fatigue or pressure.
Earlier proactive commands also do not globally delay later proactive commands beyond the later command's own first available future minute; insertion uses the first unused minute after both the current replay minute and the command minute.

When no commands exist, the source event order is returned exactly as provided.

## Initial projection rules

### Lower tempo/pressing

Suppresses one future fatigue-warning event after the command minute.

Diagnostic example:

```text
54’ Lower tempo/pressing suppressed future fatigue warning at 66’.
```

### Reduce pressing or change mentality

Uses the same fatigue-relief suppression path as lower tempo, plus the command-effects projection already records the tactical pressure reduction.

### Adjust defensive line

Suppresses one future away pressure event after the command minute.

Eligible pressure events:

- chance
- free_kick
- corner
- foul
- offside

Diagnostic example:

```text
54’ Adjust defensive line reduced away pressure event at 72’.
```

### Change mentality

Injects a home tactical-shift event after the command minute:

```text
Home mentality changed after manager command.
```

### Change pressing

Injects a home tactical-shift event after the command minute:

```text
Home pressing changed after manager command.
```

## UI contract

Interactive replay view model now exposes:

```ts
projectedReplay: string[]
```

Browser section:

```text
Projected remaining replay
```

Example lines:

```text
Projected final: Home XI 1 - 0 Away XI
Remaining projected events: 90’ Full time.
54’ Lower tempo/pressing suppressed future fatigue warning at 66’.
Projection uses command effects signature: cmd-054-01-lower-tempo-pressing.
```

## Current limitation

P15B projection is intentionally scoped. It does not yet:

- resimulate chances from team/tactic inputs
- mutate the authoritative `MatchResult`
- persist replay sessions on the server
- substitute real players
- alter the currently displayed score-so-far before future events reveal

## Next transition

P15C should make the command log feed an authoritative resumable match session, where remaining events are regenerated by simulation inputs instead of projected by event transforms.
