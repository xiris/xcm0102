# Hydration Warning Noise Contract

## Purpose

The app should not show false-positive React hydration mismatch warnings when browser extensions add attributes to the document before React hydrates.

## Root cause

The reported warning showed this mismatch on the root layout body element:

```text
<body
-  cz-shortcut-listen="true"
>
```

`cz-shortcut-listen` is injected by a browser extension before client hydration. It is not generated by the app, and repository search confirmed the app does not use `Date.now()`, `Math.random()`, `typeof window`, or `cz-shortcut-listen` in the React render path.

## Fix

`app/layout.tsx` sets:

```tsx
<body suppressHydrationWarning>{children}</body>
```

This is intentionally scoped only to the root body element so extension-injected attributes do not produce noisy hydration mismatch warnings.

## Regression coverage

`tests/web/rootLayout.test.ts` verifies the root body element carries `suppressHydrationWarning`.

## Important limitation

This suppresses browser-extension attribute noise at the body boundary. It must not be used to hide real app-generated hydration mismatches deeper in the tree.

If future warnings point to app-owned components or content differences, investigate and fix the underlying deterministic rendering issue instead of adding broader suppression.
